## 1.0.1 真机滚动修复

2026-10-20 在已连接的 vivo V2436A 上验证：安卓使用固定视口与独立主内容滚动容器，主内容和弹窗滚动锁分别处理。真实 Android 滑动输入验证向上/向下滚动、图表/页尾区域滑动、取消弹窗后继续滑动。验证前后持久任务数据摘要一致，用户反馈「现在没问题」。这不等于所有 vivo 机型或全部业务流程都已完成实机验收。

## 1.0.2 真机高刷新率验证

2026-10-20，vivo V2436A、Android 16 / API 36、展开屏 2200×2480、WebView 155。原始版本屏幕实际模式为 60 Hz，真实滑动的四秒 WebView rAF 采样约 59.3 FPS，中位间隔 16.7 ms。加入原生刷新率请求后，系统窗口报告 `preferredRefreshRate=120.00001`，显示器实际 modeId=1、renderFrameRate=120.00001；同样滑动采样约 119.9 FPS，中位 8.3 ms、P95 8.4 ms。回到桌面后窗口已释放刷新率偏好；重新打开后约 119.7 FPS。

真实上下滑动、从图表/页尾滑动、取消弹窗后继续滑动均通过；测试前后持久任务数据摘要一致。18 项领域测试再次通过，生产静态构建与原生 Gradle 构建通过。网页 UI 未在此次刷新率改动中调整，浏览器 16 项结果为前一版记录。

帧回调节奏并非逐帧呈现证明，也不承诺所有场景零掉帧。以上是该手机展开屏的有限采样；折叠屏监听已实现，物理折叠切换和其他机型尚未实测。未更改手机全局刷新率、温控或省电策略。

## 1.1.0 本地 Qwen 4B / 9B 真机验证

设备为 vivo V2436A / X Fold5、Snapdragon 8 Gen 3、Android 16、16 GB 级内存。1.1.0（versionCode 4）已覆盖安装，两个固定版本 Q4_K_M 文件已通过 USB 预置并由 App 原生层完成 SHA-256 校验。引擎为固定提交的 llama.cpp、CPU 4 线程、4096 token 上下文，每次只驻留一个模型。

以下是有限的合成中文短问答与单任务 JSON 测试，不是持续性能或不同模型质量评测。首字时间包含提示词处理；输出速度按首字后的生成间隔计算，不含模型加载。

两个模型均完成真实中文问答、可解析 JSON 草稿、主动取消、单模型状态与释放测试。4B 在最终 APK 上再次执行；9B 在同版原生引擎候选包上执行，最终包随后补充了处理期间亮屏与前端提示调整。脚本逐次比较任务存储摘要，确认未改变已有任务。浏览器 AI 操作测试使用原生接口桩，与这些真实推理测试分开统计。

最终 APK 内还完成真实 4B 的「生成任务 → 显示可编辑草稿 → 修改开始时间」流程：19:30 开始的 60 分钟工作任务触发保护时段校验并禁用保存；改为 14:00 后允许保存。测试选择放弃草稿，没有向个人任务库加入测试内容。系统桌面前台状态经安卓 Activity 记录确认，返回 App 后模型已释放；系统模型文件选择器取消后解除忙状态，两个校验通过的文件保留。上述验证后任务摘要与升级前一致。WebView 调试连接中的 document.visibilityState 未可靠反映系统后台状态，因此不作为后台释放判据。截图见 preview-ai-android.png。

AI 验证后再次在最终包执行真实上下滑动、图表/页尾滑动和取消弹窗后滚动，全部通过。四秒真实滑动 rAF 采样 478 个间隔，平均 119.46 FPS，中位 8.3 ms、P95 8.4 ms；模型当时已释放，此结果不代表持续推理时的流畅度。前后任务摘要未变化。

构建使用 JDK 21、NDK 28.2.13676358 与 CMake 3.22.1；原生库和 APK 构建通过。许可文本随 APK 打包，权重不包含在 APK 和源码压缩包内。CPU 路线已运行；GPU/NPU、长时间发热与耗电、峰值内存、其他设备和完整成功的系统文件选择器大模型导入流程尚未验证。文件导入代码包含大小/摘要校验和原子替换，但 USB 预置测试不等同于系统文件选择器导入测试。
